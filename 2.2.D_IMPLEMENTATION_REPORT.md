## Key Implementation Decisions Honored
- Private disk `property-images` + guarded route for all new images
- Only 2 new migrations; legacy `images/demo` public untouched
- Published property returns to `pending` on gallery change OR amenity change (but reorder/cover-only keeps `published`)
- Create page shows «إدارة الصور والمرافق» link after draft save/submit without changing existing behavior
- Amenities: normalized tables (`amenities` + `property_amenity`), no JSON
- 18 amenities seeded idempotently
- GD re-encoding strips EXIF; no thumbnails
- 5MB/image, 20 images/property, 200–6000px, 36MP pixel cap
- Owner mount/action gating: components allow view in Sold/Rented but abort 403 on save/upload/delete/cover/replace; admin bypass via policy
- `returnToReview()`: published→pending on gallery/amenity change; `published_at`/`published_by` retained
- Transactions + `lockForUpdate` to prevent concurrent cover exceed/limit violations
- Clean temporary files on failure; delete old file only after successful commit
- Soft-delete property → images 404; restored property remains reachable
- No production DB commands; dev/test DB only used
